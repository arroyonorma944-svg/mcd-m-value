# 麦值 · M-Value

> 读取你的麦当劳历史订单，用一个 0–100 的分数，度量你对金拱门的浓度。

**M-CODE 2026 麦当劳程序员创意开发大赛参赛作品**

---

## 这是什么

**麦值（M-Value）** 是一个基于麦当劳 MCP 能力的 Skill。它不给你推荐套餐、不帮你领券，只做一件别人没做的事：**把你自己的订单历史，变成一张可以拿去比较的成绩单**。

输入是一段订单历史，输出是一个 0–100 的 M 值，加五个维度的拆解，加几句你大概率没意识到的洞察。

```text
你的 M 值：82 / 100
🙏 麦门虔诚者 —— 你的手机桌面应该有金拱门

忠诚度 91 ██████████████████░  跨度 21 个月 / 共 26 单 / 月均 1.2 单
依赖性 65 █████████████░░░░░░  夜宵 9 次 / 非饭点 9 次 / 工作日 26 次
专一度 67 █████████████░░░░░░  巨无霸占 33%，前三占 90%
包容度 99 ████████████████████  付费单 26/26 单 / 自付单均 44.2 元
探索度 91 ██████████████████░  5 种商品 / 2 家门店
```

### 「M」是什么意思

M 是 **McValue** 的首字母，也是**麦当劳**的 M。取「麦值」这个读音。

如果有人一定要往别处想，那说明这个双关设计成功了。本项目的 M 值只衡量一件事：**你在麦当劳身上投入了多少**。评分全部来自订单客观统计，不涉及任何主观标签。

## 为什么做这个

市面上的麦当劳 MCP 项目，90% 在做三件事：推荐套餐、算热量、找优惠。这三件事都有明确的最优解，做法趋同，做出来的东西也趋同。

但有一类数据几乎没人动：`order-list` 返回的历史订单。它记录的不只是消费，还有**你的行为模式**——几点会想起麦当劳、多久一次、是不是认死那几样、愿意为它花多少钱。

这些数据合起来，能回答一个比「今天吃什么」更有意思的问题：**你到底有多爱它。**

而且这个答案天然适合分享。人不介意被人格测试，人介意被 AI 说教。

## 五维模型

M 值不是拍脑袋定出来的，五个维度各对应订单里的一种可观测行为。

| 维度 | 权重 | 衡量什么 | 数据信号 |
|---|---:|---|---|
| **忠诚度** | 30% | 你来了多久、来了多少次 | 首末订单跨度 + 月均单量 |
| **依赖性** | 22% | 你在什么时间会想吃它 | 夜宵(22–5点)占比 + 非饭点占比 + 工作日占比 |
| **专一度** | 20% | 你是不是只点那几样 | Top1 单品占比 + Top3 覆盖率 |
| **包容度** | 16% | 你愿不愿意为它掏真金白银 | 自付单比例 + 自付单均金额 |
| **探索度** | 12% | **反向**：你越爱尝鲜，M 值越低 | 每单新品数 + 门店数 + 渠道数 |

### 等级

| M 值 | 等级 | 描述 |
|---:|---|---|
| 90–100 | 🍔 麦门圣徒 | M 值天花板，汉堡因你而存在 |
| 75–89 | 🙏 麦门虔诚者 | 你的手机桌面应该有金拱门 |
| 60–74 | 😌 资深麦友 | 熟悉的柜台，熟悉的味道 |
| 40–59 | 🚶 路过型食客 | 有缘才见，无缘不念 |
| 20–39 | 🧭 尝鲜游客 | 你只是刚好饿了 |
| 0–19 | 👽 麦门陌生人 | 这张订单表基本都是别人的故事 |

### 设计上的两个自我否定

写这个模型的过程中推翻了两次设计，都记在这里，因为这两次推翻决定了最终的分数量纲。

**一、专一度不能用香农熵。**

最初用归一化熵衡量「商品分布的集中程度」。实测发现它有个致命缺陷：熵只反映分布是否均匀，**与到底有几种商品无关**。一个只点 4 种商品但每样都点的人，和一个点了 50 种商品且均匀分布的人，归一化熵都可能接近 1，被判定成同样不专一。

但这两类人的行为完全不同。改用绝对占比（Top1 单品占比 + Top3 覆盖率）后，问题消失：只点 4 种的人专一度 74，点 12 种各一次的人专一度 0。

**二、探索度不能用熵，且需要数量系数。**

探索度早期直接复用熵，导致「6 单 7 种商品」被算出「很集中」——因为熵在小样本下会被系统性压低。改用三个不依赖样本量的绝对指标（每单新品数、门店数、渠道数），并乘以一个随订单量增长的数量系数，避免「3 单 3 家店」直接满分。

**三、阈值标定调整过一次。**

初版阈值设得过于保守（跨度 18 个月才算满分、月均 2 单才算高频），结果一个 26 单、跨 21 个月的重度用户只拿到 64 分。评分区间被压扁，区分度不足。下调阈值后，重度专一用户 87 分、分散尝鲜用户 58 分，"麦门圣徒"这一档才真正可达。

**所有阈值都写在 `src/mvalue.js` 的注释里，可以改，改完用 `node test.js` 验证分布。**

## 安装

项目零依赖，用浏览器打开即可运行。

```bash
git clone <your-repo-url>
cd mcd-m-value
# 方式一：直接打开
open index.html        # macOS
start index.html       # Windows

# 方式二：本地起服务（推荐，避免部分浏览器的 file:// 限制）
python -m http.server 8000
# 然后访问 http://localhost:8000
```

### 在 WorkBuddy 中接入麦当劳 MCP

M 值的真实计算依赖麦当劳 MCP 的 `order-list`。配置方式：

1. 打开 WorkBuddy → 左侧「专家·技能·连接器」→「连接器」页签
2. 右上角「自定义连接器」→「配置 MCP」
3. 填入下面的 JSON，**把 `YOUR_MCP_TOKEN` 换成你自己的 Token**

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

4. 回到「自定义连接器」，启用 `mcd-mcp`
5. 在对话框里说：**「算算我的 M 值」**

MCP Token 在 [open.mcd.cn/mcp](https://open.mcd.cn/mcp) 用手机号登录后，进入「控制台」申请。

## 使用示例

### 在 WorkBuddy 对话中

```text
算算我的 M 值
```

Skill 会自动调用 `order-list`，然后：清洗订单 → 五维打分 → 生成洞察。

进阶用法：

```text
算算我的 M 值，顺便告诉我今年在这些订单里吃了多少钠
```

这时会额外调用 `list-nutrition-foods`，把订单商品与营养表做名称匹配，累加钠含量。

### 直接在浏览器里跑

`index.html` 内置三套示例画像（重度专一 / 轻度路过 / 甜品党），点「换一套示例数据」即可切换。这三套数据是**确定性生成**的，不是随机数——同样的画像永远得到同样的分数，方便截图对比。

### 作为库调用

```js
const M = require('./src/mvalue.js');

const orders = await mcp.call('order-list', {});   // MCP 返回的 data.list
const report = M.computeMValue(orders.data.list, {
  now: new Date(),
  nutrition: nutritionTable,   // 可选，来自 list-nutrition-foods
});

console.log(report.mValue);        // 82
console.log(report.tier.name);     // 麦门虔诚者
console.log(report.dimensions);    // 五个维度的明细
console.log(report.insights);      // 洞察文案数组
```

## 边界与已知限制

诚实说明，避免误用。

| 限制 | 说明 | 处理方式 |
|---|---|---|
| **订单量不足** | 少于 3 单时任何分数都不可信 | 直接返回 `insufficient`，不硬凑分数 |
| **分析窗口** | 只统计最近 24 个月 | 超出窗口的订单被丢弃，避免多年前的数据稀释画像 |
| **钠估算覆盖率** | 营养表以主餐为主，甜品、酱料、套餐组合名匹配率低 | 覆盖率 < 40% 时标记 `reliable: false`，不在页面展示该结论 |
| **套餐拆解** | MCP 返回的套餐拆成多个商品，无价格分摊 | 专一度按「出现次数」而非「份数」计算，避免套餐重复计数 |
| **不能识别同一商品改名** | 商品名称变体无法归并 | 未做处理，属于已知局限 |
| **Demo 不连接真实 MCP** | 纯静态页面无法安全存储 Token | 页面只演示评分逻辑，真实查询走 WorkBuddy Skill |

### 关于「M」的用词

评分维度全部是客观统计量，不含任何主观人格标签，也不构成对个人性格的评价。项目名中的 M 指 McValue / 麦当劳，与任何亚文化用语无关。

## 技术说明

- **零依赖**：`mvalue.js` 是纯 ES5+ 函数集合，不引入任何第三方库
- **确定性**：不使用 `Math.random()`，同样的订单输入永远得到同样的分数
- **可测**：`node test.js` 跑全部边界用例
- **纯前端**：页面不上传、不留存任何数据，所有计算在浏览器内完成
